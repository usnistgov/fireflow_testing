Testing environment for [fireflow](https://github.com/usnistgov/fireflow).

The main purpose (so far) is to verify that `fireflow` has support for opening a
large variety of files, ideally with little intervention.

Note that data integrity (that is, ensuring that the data in the file is the
same data that is actually presented) is intended to be tested in the
[fireflow](https://github.com/usnistgov/fireflow) repository itself.

# Caveats

This repository is currently under heavy/fast development. Documentation may be
out of date.

Particularly, the goal is to scale this to many 100k's worth of FCS files from
the open internet. Large architectural changes (including splitting some
functionality into different repos and pipelines) will likely be necessary.

# Obtaining files

See [the config](config/config.yml) for a list of all files currently being
tested. More conveniently, a file manifest is generated by the pipeline and will
be available in `results/metadata/file_sources.tsv` which will be easier to
read.

Currently, the total space required is ~50G for all downloaded FCS files.

The following repositories are currently being used:

## Flow Repository

FR currently has no API for downloading automatically. These must be obtained
manually and placed in `resources/flow_repository/<FR_ID>` uncompressed with no
further modification. The configuration is assumed to point to the correct files
within this directory.

## Immport

Downloading from Immport should just work with an API key. This will require
setting up an Immport account.

This key must be in the environment before running the pipeline. A script is
provided here for convenience:

``` bash
export IMMPORT_TOKEN=$(./get_immport_token.sh)
```

## Zenodo (and Dryad)

Nothing special needs to be done for Zenodo/Dryad since all files in the
configuration should be downloaded via their public API (which doesn't require
credentials).

Dryad requires and API key and can be obtained analogously to Immport. This must
be run prior to the pipeline:

``` bash
export DRYAD_TOKEN=$(./get_dryad_token.sh)
```

NOTE: eventually everything will be done through Zenodo's API since all Dryad
data is a subset of that indexed in Zenodo. Dryad is here because as a
historiral holdover that has yet to be removed.

# Running pipeline

Ensure you have `mamba` (or `conda` for the patient) installed.

Clone this repo and navigate to the root. Run the following:

``` bash
mamba env create -f env.yml
```

Then run the pipeline:

``` bash
snakemake -c 20 --use-conda --configfile=config/config.yml all
```

# Interpreting results

See `results/summaries/summary.html` for full report of testing results,
including features used and errors found.

`results/metadata` and `results/compliance_errors` contains a dump of tsv files
with the data used to make the summary report above. There are also files with
data not in the report, such as all non-standard keywords found in the tested
files.
